# 로그인 세션 기록·목록·종료 TODO

사용자가 자신의 로그인 세션을 구분하고 불필요한 세션을 종료할 수 있도록 할 때의 작업을 기록한다. 이 문서는 향후 구현 범위이며, 아래의 목록·원격 종료 기능은 아직 제공하지 않는다.

## 현재 구현

- 로그인마다 새 `session_id`를 만들고 `tlab_refresh_token`에 `user_account_id`, 현재 refresh token 해시, 생성 시각, 만료 시각을 저장한다. 같은 사용자의 여러 세션을 허용한다.
- `refresh_token_repository::find_all_by_user_account_id`로 사용자별 refresh 세션을 조회할 수 있고, `delete_by_user_account_id_and_session_id`로 한 세션을 삭제할 수 있다. 현재 이 조회를 사용자에게 제공하는 API는 없다.
- access token의 현재 `jti`는 프로세스 메모리의 `(user_account_id, session_id) → jti`에 저장한다. 현재 로그아웃은 자신의 access token `jti`가 일치할 때 해당 항목을 제거한다. 이 저장소는 향후 Redis 교체 대상이다.
- `tlab_user_identity.last_login_at`은 로그인 수단별 마지막 로그인 시각이다. 세션별 로그인·활동 기록은 아니다.
- 세션에 기기 표시 정보나 마지막 활동 시각은 저장하지 않는다. 현재 로그아웃 시 refresh 세션 행을 삭제하므로 종료된 세션의 이력도 남지 않는다.

## 구현할 동작

1. 로그인 시 세션별 표시 정보를 기록한다. `session_id`는 내부 식별자로 유지하고, 브라우저·운영체제·기기 종류 등은 사용자가 세션을 알아보기 위한 별도 정보로 둔다. HTTP `User-Agent` 등에서 얻은 값은 부정확하거나 비어 있을 수 있으므로 표시용으로만 사용한다. 정확한 기기 이름이나 고유 기기 식별자로 취급하지 않는다.
2. 세션별 로그인 시각과 마지막 활동 시각을 구분한다. 마지막 활동의 갱신 기준과 쓰기 빈도를 구현 전에 정한다. `tlab_user_identity.last_login_at`은 로그인 수단별 요약값으로 유지하고 세션 목록의 원본으로 사용하지 않는다.
3. 인증된 사용자의 활성 세션 목록을 `user_account_id` 기준으로 조회한다. `session_id`, 표시용 기기 정보, 로그인 시각, 마지막 활동 시각, 만료 시각, 현재 세션 여부를 제공한다. refresh token 해시와 access token `jti`는 응답에 포함하지 않는다. 만료·종료된 세션을 목록에서 어떻게 제외하고 정리할지도 정한다.
4. 사용자가 목록에서 선택한 `session_id`를 종료할 수 있게 한다. 서버에서 대상 세션이 요청한 사용자의 소유인지 확인하고, 해당 refresh 세션을 무효화한 뒤 `(user_account_id, session_id)`의 현재 access `jti`도 제거한다. 다른 세션은 유지한다. 자기 세션을 종료한 경우 클라이언트의 인증 쿠키와 화면 상태도 정리한다.
5. 선택한 세션 종료는 현재 로그아웃의 `jti` 일치 조건과 구분한다. 다른 세션의 access token을 가지고 있지 않아도 소유자가 세션 ID로 종료할 수 있어야 한다. 종료와 refresh 재발급이 경합해 세션이 되살아나지 않도록 DB 처리와 access 등록 순서를 함께 검토한다.
6. 필요하면 사용자 전체 세션 종료 기능을 별도로 추가한다. 새 로그인 때 기존 세션을 자동 종료할지는 별도 정책으로 결정한다. 다중 세션 허용이라는 현재 동작을 기본으로 둔다.

## 저장과 감사 기록의 경계

- 활성 세션 목록의 원본은 사용자와 `session_id`에 연결된 세션 데이터로 둔다. 기존 `tlab_refresh_token`을 확장할지, 별도 세션 테이블을 둘지는 종료 이력 보관 여부와 refresh token 만료·삭제 정책을 정한 뒤 결정한다.
- 로그인 성공·실패, 세션 종료 주체와 시각 등 사후 추적이 필요해지면 별도의 감사 이벤트로 기록한다. 감사 기록을 현재 활성 세션 목록의 원본으로 사용하지 않는다.
- 감사 기록을 도입할 때는 보관 기간과 개인 정보 범위를 정한다. IP 주소나 원본 `User-Agent`의 저장 필요성도 그때 검토한다.

## 구현 시 확인할 사항

- 동일 사용자의 여러 세션이 목록에 각각 나타나고, 한 세션 종료 후 나머지 세션의 access·refresh token은 계속 유효한지 확인한다.
- 타인의 세션이 목록에 노출되지 않고, 타인의 `session_id`로 세션을 종료할 수 없는지 확인한다.
- 종료한 세션의 access token과 refresh token이 모두 거부되는지, refresh와 종료가 동시에 요청될 때도 종료 상태가 유지되는지 확인한다.
- 기기 정보가 없거나 해석할 수 없어도 세션을 표시하고 종료할 수 있는지 확인한다.
- 여러 서버 인스턴스에서 즉시 종료가 필요하면 [Access token 무효화 확장안](../../tlab-boilerplate/docs/plan/access-token-revocation.md)의 Redis 전환과 함께 검증한다.
